# fxquant

面向 B站网页游戏《FX 简单!》的本地量化交易程序。

**当前版本：v0.6（真实交易闭环 + 提示自动关闭）**

---

## 一、最重要的事：两条红线

这个程序在处理"什么信息可以使用"上有严格约束。这不是洁癖，而是量化能不能成立的根本问题。

### 红线 1：不读取未来走势

策略在任意时刻只能看到**截至该时刻已经发生的价格**。
程序在机制上保证这一点，并在 `test_no_lookahead.py` 里用四种方法反复验证。

### 红线 2：不使用程序内部实现的知识

这条比第一条更隐蔽，也更容易被忽略。

游戏的价格是怎么生成的——随机数公式、漂移项、事件概率、内部参数表——
这些都属于**程序内部实现**。哪怕能通过阅读前端代码拿到，
使用它也和"偷看未来"没有本质区别：

- 它让策略在回测里看起来很准，但那个"准"来自作弊，不是来自市场规律；
- 它无法迁移到任何真实市场；
- 对方一旦改版，策略立刻失效。

**所以本项目里不存在任何对目标行情生成算法的复刻或依赖。**

作为对比，以下信息是**允许**使用的：

| 信息 | 为什么可以用 |
|---|---|
| 价格历史 | 就是市场本身，量化研究的唯一合法原料 |
| 保证金 / 杠杆 / 手续费规则 | 界面和教程里直接展示给玩家的公开规则 |
| 爆仓线（亏损达保证金 80%） | 教程明确说明的公开机制 |
| 市场快讯的出现 | 玩家在界面上能实时看到的公开事件 |

注意最后一条：快讯**只被当作"不确定性升高"的标记**用于收紧风控
（降低仓位、减半风险预算），**不去解析它对价格的方向性影响**——
因为那个方向性影响属于内部实现。

---

## 二、既然不能用内部知识，策略怎么赚钱？

答案是：**让系统自己从已发生的价格里学**。

### 多因子 + 自适应权重

程序把**四个方向因子**当作候选预测器，另有一个波动率调节项：

| 因子 | 含义 |
|---|---|
| trend | 快慢 EMA 乖离 + 趋势斜率 |
| momentum | 变化率 ROC + 动量加速度 |
| reversion | 布林带 z-score 反向（超买看空、超卖看多） |
| cycle | **谱分析**：用周期图找主导周期并外推一个时点（见下文） |
| volatility | 波动率状态，只调节信号强度，不产生方向 |

每个因子是看多还是看空、有多可信，**不由代码写死**。

程序会持续做这件事：在每个时点登记各因子的**取值**，
等固定期数（`eval_horizon`）后用**已经发生的价格**回头检验，
用**信息系数（IC）**衡量预测力，再按统计显著性动态分配权重。

#### 学习机制的四条关键设计

1. **用 IC，而不是"方向命中率"**。
   早期版本把每条预测压缩成 ±1（因子看涨就看涨），只统计方向对错。
   这丢掉了因子**幅度**信息：取值 0.9 的强信号与 0.16 的弱信号被同等对待，
   估计效率很低。在真实只有 0.05 量级的 IC 上，这几乎不可能达到统计显著。
   现在直接用协方差口径
   `IC = cov(因子, 未来收益) / (sd(因子)·sd(收益))`，
   与因子缩放无关，同样样本量下更容易识别出真实 edge。

2. **保留符号 —— 反向因子要"反着用"**。
   如果某因子的 IC 显著为负，说明它在这个市场是**反向指标**，
   系统会给出**负权重**把它翻过来用，而不是把它丢掉。
   （这里曾有一个致命 bug：`math.copysign(mean, 1.0)` 恒返回正数，
   导致权重永远无法为负，学习机制**永远没法反用任何因子**。）

3. **没有 edge 就归零，而不是退回等权**。
   当所有因子都通不过显著性门槛时，权重**全部置零** → score=0 → 不开仓。
   等权会让策略在"还没学到任何东西"时按因子平均方向开仓，纯属白付成本；
   在无结构的随机行情里，**少交易本身就是正收益策略**。
   （权重初始值也设为全零，同样出于这个理由。）

4. **降采样，避免 t 统计量被高估**。
   只每隔 `eval_horizon` 个时点登记一次预测。
   否则相邻时点发出的预测共享同一段未来价格，样本高度重叠且不独立，
   t 统计量会被严重高估 —— 因子看起来"显著"，实际只是噪声的重复计数。

#### 显著性门槛的取值教训

门槛最初设为 `t = 2.0`（约 95% 置信度），结果造成**"过度保守"死锁**：

> 真实 IC ≈ 0.05 的因子要达到 t=2.0 需要约上千个独立样本，
> 而回看窗口只有几百 → 任何因子都永远不显著 → 权重恒为 0
> → 永不交易 → 在线校准也永远拿不到样本。整条链自我锁死。

现在取 `t = 1.0`（单边约 84% 置信度）是更现实的选择：
实盘里 IC≈0.05 的信号本来就达不到 95% 置信度，强行要求只会导致策略完全不动作。
噪声风险由下游两道防线兜住 —— **在线校准的成本门槛 + 风控**。

#### 成本感知开仓门槛

信号只是**概率优势**，而交易成本是**确定支出**。开仓不能只看"信号够不够强"，
还要看"这点信号强度换来的预期收益，够不够覆盖成本"。

预期收益的**首选来源是在线校准**（`ScoreCalibrator`）：
用已实现价格在线估计 `beta = cov(score, 未来收益) / var(score)`，
于是门槛会自动适配信号此刻的真实强度 —— 强则放宽、弱则收紧。
早期版本用硬编码常数（假设 score=1.0 对应 0.5% 收益），
当真实预测力只有它的四分之一时，门槛会放行大量负期望交易。

> **关于点差**：实测游戏行情接口只提供**单一价格**，界面没有并列的买卖价，
> 开平仓按同一价格成交，点差成本约为 0。真实的确定成本只有手续费
> （5 倍杠杆往返约 1.5bp）。早期把点差臆测为 8bp 是**过度保守**，
> 会把往返成本抬到约 9.5bp，直接把所有交易挡在门外、策略永远空仓。
> 若观察到真实价差，用 `--spread` 调整即可。

### 谱分析因子：为什么需要 `cycle`

普通的动量/反转因子只能捕捉**相邻时点**的自相关。若价格里存在周期性成分
（这在真实外汇/商品市场里很常见），单周期动量往往测不出来：
一个完整周期走下来净位移接近零，动量因子自然失效。

正确做法是**谱分析**（periodogram）：

1. 取最近 `W` 个收益，去均值；
2. 在**正交频率网格**（周期 = `W/k`，即离散傅里叶变换的天然格点）上扫描，
   对每个 `k` 计算复相关幅度
   `C = Σ r[i]·cos(ωi)`、`S = Σ r[i]·sin(ωi)`，`ω = 2πk/W`，
   功率 `P = (C² + S²) / W²`；
3. 取功率最大的频率，若它解释的方差比例低于 `cycle_min_frac`，
   视为**没有可信周期** → 返回 0；
4. 由 `(C, S)` 反解振幅与相位并外推一个时点。

数学依据：若 `r[i] ≈ A·sin(ωi + φ)`，则 `C ≈ (A·W/2)·sin φ`、`S ≈ (A·W/2)·cos φ`，
因此 `A = 2√(C²+S²)/W`、`φ = atan2(C, S)`；
外推到 `t = W` 时相位正好前进 `2πk`（整数倍），故预测值 `= A·sin(φ)`。

两个关键实现细节（都是踩过坑之后改的）：

- **用正交频率网格，不要用一组"好看的"整数周期**。
  早期版本扫描周期 {4,6,8,...}，当真实周期不在候选格点上时会发生**频谱泄漏**，
  功率大幅下降，导致明明有周期却检测不出来。
- **输出要按当期波动率归一化**。
  否则该因子的量级远小于其他因子（实测均值 0.02 vs 趋势的 0.64），
  会被自适应机制当作无效信号而忽略。归一化后 cycle 市场的因子均值
  从 0.02 提升到约 0.16，而 flat 市场仍然很低 —— 说明它捕捉的是真实结构，
  不是过拟合噪声。

> 周期**不被告知**：周期从 `min_period` 到 `max_period` 全范围扫描，
> 是否存在周期完全由数据本身决定。

### 诚实的评估台

策略到底有没有 edge，不能靠"跑一次看看"来判断。项目自带一个**中立**的评估台
（`fxquant/eval_market.py` + `eval_harness.py`）：

- 用金融学通用工具合成市场：收益一阶自相关（AR(1)）+ 周期性漂移
- **不含目标游戏的任何参数**（那等于用内部知识优化，与偷看未来等价）
- 各市场**无条件波动率相同**（`sigma_eps = vol · sqrt(1-phi²)`），便于公平对比
- 每个标的的周期与相位**独立随机生成**，策略无从预先得知
- 多市场 × 多随机种子 × 多点差档位，看的是分布而不是单次结果

判读标准（**看梯度，不看单点**）：

| 市场 | φ | 期望表现 | 含义 |
|---|---|---|---|
| flat | 0.00 | 接近保本 | 无结构时能克制，不白付成本 |
| trend / revert | ±0.22 | 略优或持平 | 弱结构，几乎不可交易 |
| trend_mod / revert_mod | ±0.60 | 明显盈利 | 中等结构被捕捉 |
| trend_strong / revert_strong | ±0.85 | 显著盈利 | 强结构被捕捉 |
| cycle | 正弦漂移 | 明显盈利 | 周期结构被捕捉 |

随结构增强，收益应当**单调改善**；若强结构档上依然不赚钱，
才说明策略真的没有 edge。

**为什么分三档强度？** 早期评估只用了 φ=±0.22 一档。
用因子 IC 诊断（`python diag_factor_ic.py`）实测发现，该档下最有效因子的
IC 仅约 0.05，而强结构档（φ=0.85）可达 **0.24** ——
也就是说弱档本身就"几乎无结构"，策略在弱档上赚不到钱是正常现象，
并不能说明策略有问题。分档之后才能看出真正的能力边界。

各市场下的因子 IC 实测（`h` 为预测期数）：

| 市场 | trend | momentum | reversion | cycle |
|---|---|---|---|---|
| flat | −0.005 | −0.003 | +0.002 | +0.010 |
| trend .22 | +0.008 | +0.033 | −0.055 | +0.017 |
| trend .60 | +0.044 | +0.099 | −0.141 | +0.072 |
| trend .85 | +0.095 | **+0.168~0.235** | **−0.186~−0.249** | +0.064~0.092 |
| revert −.60 | −0.039 | **−0.156** | **+0.233** | — |
| cycle | −0.032 | −0.007 | +0.001 | **+0.069~0.074** |

两个要点：

- **flat 上所有因子 IC 都接近 0** —— 说明它们不会在无结构时"看出"结构，
  这是好事；若某个因子在纯随机游走上也有可观 IC，那多半是构造性偏误。
- **revert 市场上动量/反转的 IC 符号正确翻转** —— 说明因子确实在度量
  "市场此刻是延续还是回摆"，而不是写死某个方向。

用法：

```bash
# 全部市场 × 20 个随机种子
python eval_harness.py

# 指定市场 / 指定点差档位（点差单边，占价格比例）
python eval_harness.py trend revert --spread=0.0004
```

也可以直接调用 `report()` 一次跑多个点差档位，观察成本敏感度：

```python
from eval_harness import report
for sp in (0.0, 0.0004, 0.0008):
    report(["flat", "trend", "revert", "cycle"], seeds=range(1, 11),
           ticks=1500, spread=sp)
```

> **重要**：`run_once` 会把 `cfg.strategy.spread_estimate` 同步设为传入的
> `spread`，让"成本门槛里假设的点差"与"实际结算用的点差"保持一致。
> 否则门槛会按一个并不存在的成本去过滤交易，表现为过度保守、几乎不交易。

#### 最终版实测结果（诚实版）

以下数据由 `python final_report.py 12 1500` 生成：8 档市场 × 每档 12 个随机种子，
`cost_multiple = 3.0`。

> ⚠️ **口径说明**：下表是在 `entry_score = 0.45` 时跑出来的。
> 之后开仓阈值默认值下调到 **0.35**（原值在真实行情里几乎不产生开仓意图），
> 因此下表的"平均开仓"列会低于新阈值下的实际值 ——
> 趋势档结论（唯一稳健 edge 在 `trend_strong`）不受影响，但精确数字
> 需要用 `final_report.py` 在 0.35 下重跑。

**点差 0（游戏只有单一报价，确定成本仅手续费）：**

| 市场 | 平均收益 | 中位 | 胜率 | t 值 | 平均开仓 |
|---|---|---|---|---|---|
| flat（无结构） | −0.88% | −0.67% | 33% | −2.16 | 8.2 |
| trend (φ=.22) | −1.77% | −1.65% | 17% | −2.50 | 9.9 |
| trend_mod (φ=.60) | +2.52% | +1.71% | 58% | +1.24 | 28.1 |
| **trend_strong (φ=.85)** | **+48.03%** | +49.35% | **100%** | **+8.52** | 33.4 |
| revert (φ=−.22) | +0.89% | +0.81% | 67% | +1.40 | 8.4 |
| revert_mod (φ=−.60) | +1.53% | +1.05% | 75% | +1.97 | 14.6 |
| revert_strong (φ=−.85) | +0.04% | +0.11% | 50% | +0.23 | 3.3 |
| cycle | +1.88% | +2.04% | 75% | +1.74 | 12.3 |

**点差 4 bp（成本敏感度对照）：**

| 市场 | 平均收益 | t 值 | 平均开仓 |
|---|---|---|---|
| flat | −0.45% | −0.99 | 2.8 |
| trend | −0.56% | −1.52 | 1.8 |
| trend_mod | −0.10% | −0.08 | 9.6 |
| **trend_strong** | **+42.60%** | **+6.64** | 32.8 |
| revert_mod | +0.08% | +0.36 | 1.4 |
| cycle | −0.12% | −0.24 | 3.2 |

**怎么读这张表（重要）：**

1. **唯一稳健的 edge 在强趋势市场。** `trend_strong` 的 +48.0%、
   t=+8.5、胜率 100%，且加上 4 bp 点差后仍有 +42.6%（t=+6.6）——
   这是统计上无可争议的能力，而且**不吃成本**。说明多因子学习机制
   在结构足够强时确实能把结构提取出来。

2. **其余档位全部落在噪声内。** `trend_mod` / `revert_mod` / `cycle`
   的 t 值只有 1 ~ 2，而 `flat` 即使扩到 24 种子 × 2000 tick
   也只有 **−0.32%（t=−0.34）**。结论：**这些正收益不构成 edge**。
   诚实地讲——策略在无结构/弱结构市场上只是"没有明显亏钱"。

3. **`flat` / `trend` 是轻微负的（−0.9% / −1.8%），这是"活着的成本"。**
   它们不是亏手续费（手续费只占 0.04%），而是拿不够强的信号去交易
   所付出的波动代价。**控制手段就是这里的 `cost_multiple` 与
   `entry_score`，不是"再调调参数就能变正"。**

4. **加成本后自动收缩，这是设计使然。** 点差升到 4 bp 时，
   弱结构市场的开仓数从 9.9 掉到 1.8——成本门槛把"优势盖不住成本"
   的机会全部挡掉。这正是 `cost_gate` 想要的行为：
   **该赚的还赚（trend_strong 几乎不受影响），不该赚的不碰。**

5. **已知短板（必须承认）：`revert_strong` 只有 +0.04%、平均 3.3 笔。**
   平仓逻辑（追踪止盈 + 240 轮超时 + 信号反转）天然偏趋势：
   在强均值回归市场里容易被反复打脸。这是下一步要改的地方。

#### 这一版修掉的两个门槛 Bug（结论因此变化）

上面这张表与更早一版的数字不同（`flat` 由 +1.44% 变为 −0.88%），
原因是修掉了两处**方向性错误**。旧数字之所以看起来更好，是 bug 造成的假象：

| Bug | 后果 | 修复 |
|---|---|---|
| **校准未就绪时返回 `beta=0`** | 成本门槛看到"预期收益 = 0"就判非正 → **永远退回不到常数兜底** → 校准就绪前完全无法交易 | 未就绪时返回 `None`（= 未知），与"算出来是零"严格区分 |
| **成本门槛把 `beta×score` 当成"本单预期收益"** | 本单方向是 `sign(score)`，真实预期收益是 `|beta×score|`。旧写法等于**只要 score<0 就一律拒绝**，策略被悄悄阉割成"只做多" | 先判 `beta>0`（信号方向是否有效），再拿 `|expected|` 比成本 |

第二处尤其隐蔽：`flat` 上那个 +1.44%（t=+2.4）**有相当一部分来自
"只做多"的方向偏置**，而不是预测力。修正后 `flat` 回到负值——
这才是"无结构市场里不该赚钱"的正常样子。

另外补了一条判据：`ScoreCalibrator` 要求窗口内有 `calib_min_nonzero`
个**非零** score 才算"就绪"。否则策略刚起步时权重全零、score 恒为 0，
样本数会迅速凑够，让校准器在只有几个非零样本时就宣布可用，
算出一个噪声主导的 β 并据此否决全部交易。

> `diag_bootstrap.py` 对比了「校准就绪前允许交易」与「禁止交易」：
> 禁止交易在多数档位略优（`flat` −0.62% vs −0.88%），
> 但**有死锁风险**（学习器若始终找不到显著因子则永不交易）。
> 默认选择允许交易（`require_calibration=False`），保底能活起来。

> **一句话总结**：这不是一个"稳定盈利 5%"的系统。
> 它是一个**在结构确实存在时能吃到、在结构不存在时基本不亏**的系统。
> 期望值取决于目标市场里到底有多少可提取的结构——而那件事
> 只能靠实盘观察，不能靠回测许诺。

#### 为什么 `cost_multiple` 最终定在 3.0

在 12 种子 × 5 档市场上扫描这个"保守度旋钮"（修复门槛 Bug 后重跑）：

| cost_multiple | flat | trend | trend_mod | revert_mod | cycle |
|---|---|---|---|---|---|
| 1.5 | −1.22% (t−1.7) | +2.13% (t+1.6) | +1.53% (t+2.0) | +2.28% (t+1.3) | −0.52% (t−1.4) |
| **3.0** | −1.99% (t−1.5) | −0.88% (t−2.2) | **+1.88% (t+1.7)** | +0.37% (t+1.0) | −1.65% (t−1.3) |
| 6.0 | +5.02% (t+2.4) | −1.77% (t−2.5) | −0.29% (t−0.6) | +0.14% (t+0.1) | +0.15% (t+0.6) |
| 12.0 | +1.88% (t+2.7) | +2.52% (t+1.2) | −0.77% (t−1.3) | −0.38% (t−0.8) | +0.02% (t+0.0) |

**诚实地说：这张表全是噪声。** 各档之间没有稳定排序 ——
x6.0 在 `flat` 上跑出 +5.02%，也正是最该被怀疑的那个信号
（无结构市场系统性赚钱 = 假利润）。没有任何一档能在所有市场上胜出。

因此不再继续调这个旋钮，保留 **3.0**：
它的含义清楚（预期收益要盖过成本的 3 倍才下注），
`trend_strong` 在 3.0 下拿到 +48%（t=+8.5）、加 4bp 成本仍有 +42.6%，
而它在弱结构市场上不产生系统性正收益。
**继续在噪声里挑参数就是过拟合**，那比留一个保守的默认值更糟。

### 风控优先

量化策略先得活下来。程序包含：

- **波动率目标仓位**：按 ATR 计算止损距离，反推仓位大小，
  使单笔最大亏损固定为权益的固定比例
- **ATR 止损 / 止盈 / 追踪止损**
- **爆仓距离保护**：即使触发止损，也保证离爆仓线有足够缓冲
- **单日亏损熔断**：当日亏损超过阈值就停止开新仓
- **新闻期降档**：快讯出现时风险预算减半
- **成本门槛**：预期毛利必须 ≥ 往返成本 × `cost_multiple`

## 四、接入游戏：执行层

引擎与执行层完全解耦。引擎只认一个 `Execution` 协议
（`state()` / `place()` / `close()` / `advance()`），
换后端不用改一行策略代码。

### 架构（DOM 版）

```
  Python 引擎（strategy / risk / live）
        │  提交任务
        v
  本地桥接服务（bridge.py，标准库 http.server，零依赖）
        │  ↑  浏览器每 200ms 轮询取任务 / 回填结果
        v  │
  Tampermonkey 脚本（browser_bridge.user.js）
        │  ① 读：从 DOM 提取报价 / 权益 / 持仓 / 新闻
        │  ② 写：设置下单表单，点击买卖按钮
        v
  游戏页面（普通 DOM）
```

**为什么走 DOM 而不是调内部接口**

初版脚本假设游戏通过 `document.modelContext.registerTool`
注册了编程接口。**实测证明这个假设不成立**：
`document.modelContext` 根本不存在（浏览器 Console 探测确认）。

定位过程也绕了弯路：一开始在错误的 frame 里找
（`s1.hdslb.com` 那个通信空壳），后来才确认游戏本体在
`bilibilitoy.com` 的 iframe 里 —— 这也是脚本必须把
「仅在顶层页面运行」设为「否」的原因。

于是改为 DOM 路线，反而更干净 —— 它做的事情和一个真人玩家
用眼睛看价格、用鼠标点按钮**完全一致**，不触碰任何内部实现：

- 价格是渲染在页面上的公开信息
- 买卖按钮是公开给玩家的操作入口
- 没有读取任何随机数公式、内部状态或未公开数据

**为什么是"浏览器主动轮询"而不是服务端推送**：
HTTP 服务没有能力主动调用浏览器里的 JS 函数，
只能让浏览器定时来取任务。

### 实测确认的页面结构

游戏本体运行在**三层 frame** 里，这是接入的第一道门槛：

```
TOP  www.bilibili.com/toy/fx-simple/index.html
 ├─ iframe[0]  www.bilibilitoy.com/toy/fx-simple   ← 游戏本体在这里
 └─ iframe[1]  s1.hdslb.com                          ← 通信空壳，无 DOM
```

实测确认的页面结构：

| 用途 | 选择器 | 说明 |
|---|---|---|
| 价格行 | `button.pair-row` | 内部 `strong[0]`=货币对，`strong[1]`=价格 |
| 货币对选择 | `#mobilePairSelect` | 下单前先选中目标 |
| 保证金 | `#marginInput` | 数字输入框，默认 500 |
| 杠杆 | `#leverageRange` | 输入框，默认 20 |
| 做多 | `button.trade-button.long` | **点击即成交，无二次确认** |
| 做空 | `button.trade-button.short` | 同上 |
| 持仓行 | `div.position-row` | 每行一笔持仓 |
| 平仓 | `button.panel-x.lite` | 在持仓行内 |
| 账户权益 | `span.money-large` | |
| 新闻 | `.news-ticker` | 只读文本，不解析方向 |
| 提示浮层 | 类名不稳定 | 见下方「自动关闭提示」 |

> **踩坑记录（重要）**：初次探测时 Console 打印出的 name 是
> `select-one` / `margin` / `leverage`，据此写选择器**全部失效**。
> 原因是 Chrome DevTools 会给**没有 name 属性**的元素生成回退名
> —— 它打印的不是真实属性。
> 必须看 `outerHTML` 才能拿到真实 id：`mobilePairSelect` /
> `marginInput` / `leverageRange`。
> 脚本现在用 `pick()` 多级选择器（真实 id 优先，旧名兜底），
> 但记住这个教训：**DOM 探测只看 outerHTML，不看打印出的 name**。

**关键交互事实：点买卖按钮直接成交，不弹任何窗。**
下单参数（保证金、杠杆）来自页面上表单的当前值。
脚本改值时必须用**原生 setter + 派发事件**，否则框架监听不到：

```javascript
function setNativeValue(el, value) {
  const proto = Object.getPrototypeOf(el);
  const desc = Object.getOwnPropertyDescriptor(proto, 'value');
  desc.set.call(el, value);                 // 绕过 React/Vue 的值劫持
  el.dispatchEvent(new Event('input',  { bubbles: true }));
  el.dispatchEvent(new Event('change', { bubbles: true }));
}
```

点击后 DOM 不是同步更新的，
所以 `placeTrade` / `closeTrade` 都用 `waitFor()` 轮询等待
新持仓出现 / 旧持仓消失，再回读成交价。

### 自动关闭提示浮层

平仓（有时开仓）之后游戏会弹一个提示框，带「确定 / 关闭 / ×」按钮，
需要玩家手动点掉。量化程序连续交易时会不断弹，既遮挡界面也拖慢节奏，
脚本会自动把它关掉。

**开关**：脚本顶部 `AUTO_DISMISS = true`，想手动看提示就改成 `false`。

**触发时机**：

- 平仓后持续清理 1.5 秒（覆盖异步弹出的情况）
- 开仓后清理 0.6 秒
- 主循环每约 5 秒兜底清一次残留

**识别方式**（不写死类名，跨版本更稳）：

1. 定位为 `fixed`，或 `absolute` 且 `z-index ≥ 10` 的元素
2. 内部存在文案匹配「确定/关闭/知道了/OK/Close/×」的按钮
3. 尺寸不是整页大小

三者同时满足才关。识别不出时**什么都不做**，绝不误关正常界面 ——
含 `.position-row` / `.order-panel` / `.trade-button` /
`.money-large` / `.news-ticker` 的容器一律跳过。

> 这属于 **UI 层操作**，与「读价格 DOM」「点买卖按钮」同性质，
> 不涉及任何行情算法或内部状态，也不给策略带来任何信息优势。

### 三种后端

| 后端 | 用途 | 是否真实下单 |
|---|---|---|
| `SimExecution` | 内存里复现游戏结算，用来测链路 | 否 |
| `BridgeExecution` | 通过桥接操作真实游戏页面 | **是** |
| `DryRunExecution` | 包装任意后端，只记录意图 | 否 |

**第 1 步：安装油猴脚本（有坑，务必逐条核对）**

在浏览器安装 Tampermonkey，新建脚本，粘贴
`browser_bridge.user.js` 的内容并保存。

脚本头部的 `@match` 必须同时覆盖两个域名（游戏本体在 iframe 里，

游戏本体在 iframe 内。默认的「是」会让脚本只在最外层
`bilibili.com` 上运行，那里**没有 `.pair-row`**，
面板会一直停在 `[顶层] 等待游戏就绪…`。

> 排查用的自检：如果面板显示 `[顶层]` 前缀，就是这个设置没生效。


**第 3 步：干跑演练**


真的连页面、真的读状态、真的算信号，但**所有下单意图都被拦截**。
用来确认信号方向、仓位大小、平仓时机符合预期。
浏览器右下角会出现状态面板，显示 `已连接 · 7 个货币对`。

> 干跑**不需要** `--yes` —— 它本身就不发真实指令。
> 启动后最多等 60 秒连接页面（期间每 15 秒提示一次进度）。

**第 4 步：实盘**

### 接入成功条件清单（缺一不可）

以上任何一条不满足，链路都会静默失败。实测下来一共 7 条：

| # | 条件 | 不满足时的表现 |
|---|---|---|
| 1 | 油猴「仅在顶层页面运行」= **否**，且**重启扩展** | 面板卡在 `[顶层] 等待游戏就绪…` |
| 2 | `@match` 包含 `bilibilitoy.com/toy/fx-simple*` | iframe 里脚本不注入 |
| 3 | 用 `GM_xmlhttpRequest` 通道 | https 页面访问 http://127.0.0.1 被混合内容拦截 |
| 4 | 表单用真实 id 选择器 | `开仓失败：找不到货币对选择框` |
| 5 | 改值用原生 setter + input/change 事件 | 值看起来改了，但下单仍是旧参数 |
| 6 | 点 `.trade-button.long/.short` 即成交 | —— |
| 7 | 点击后用 `waitFor` 等 DOM 渲染 | 回读到空持仓/旧价格 |

**混合内容（第 3 条）补充**：游戏页面是 https，
而本地桥接是 http://127.0.0.1，浏览器默认会拦截。
原生 `fetch` 需要显式声明才能放行：

```javascript
fetch(url, { targetAddressSpace: 'loopback' })
```

脚本采用双通道：优先 `GM_xmlhttpRequest`（绕过同源与混合内容限制），
失败再回退到上述 `fetch`。

### 安全开关（实盘必看）

| 开关 | 默认 | 作用 |
|---|---|---|
| `--dry-run` | 关 | 只记录意图，绝不真实下单。**game 后端下无需 `--yes`** |
| `--max-loss` | 0.20 | 累计回撤达此比例即停机 |
| `--max-trades` | 200 | 交易笔数硬上限 |
| `--yes` | 关 | game 后端**非干跑时**必须显式确认，否则拒绝启动 |

触发停机后**不会自动恢复**，需人工检查。

### live 模式的四个平仓条件

1. **盈利保护（回吐锁）** —— 浮盈峰值达保证金的 1% 后，允许回吐最多 40%，
   且**永不低于保本**。这是主力离场路径：赚过钱的单子不会再变成亏损单。
2. **灾难止损** —— 亏损达保证金 35% 时主动离场（游戏爆仓线是 80%，留足缓冲）
3. **持仓超时** —— 超过 240 轮（约 6 分钟）释放保证金
4. **信号反转** —— 方向相反且强度达开仓阈值

> 第 1 条是后加的。此前向上一端只有「浮盈达保证金 60% 才启动追踪止盈」，
> 而实测浮盈峰值中位数只有保证金的 **4.1%** —— 门槛从未触发，
> 等于没有止盈。结果是离场只剩信号反转和超时，而这两条都倾向于
> 在价格已经往回走之后才发生，表现为「本来盈利，拖到亏损」。

参数定案依据（`sweep_profit_guard.py`，8 档市场 × 12 种子 × 1500 轮）：

| 配置 | 结构档均值 | flat | trend_mod | 开仓/档 |
|---|---|---|---|---|
| 关闭保护（旧） | +9.71% | −0.72% | +4.52% | 27.9 |
| arm0.3% give20% | +29.63% | +0.83% | +43.89% | 93.6 |
| **arm1.0% give40%（选定）** | **+18.40%** | **+0.42%** | **+24.60%** | 54.2 |
| arm1.0% give50% | +17.18% | +0.27% | +24.85% | 51.7 |
| arm5.0% give50% | +12.85% | −0.63% | +9.55% | — |

> 最高分的 arm0.3% 那一档**故意不用**：它让 trend_strong 冲到 +152%，
> 且越紧越好、单调无上界 —— 这是"退出后立刻同价重进"在零成本仿真里的
> churn 伪影，不是实盘可提取的利润。选 1.0%/40% 是"明显改善结构档、
> 又没踩上伪影悬崖"的位置。

### 盈利保护参数怎么调（在真实游戏里）

`--profit-arm` 没有普适最优值，因为它取决于**这个游戏每跳的真实波动**。
合成市场的波动是我们自己设的，拿它的最优解当答案是自欺。
所以程序在收尾时会把真实跑出来的尺度打出来：

```
盈亏尺度：浮盈峰值中位 +2.4%（均值 +4.1%，最大 +27.6%）｜平仓留存中位 +0.7%
  ↑ 若留存明显低于峰值，说明回吐过多：调小 --profit-arm（更早保护）或 --profit-giveback（更早落袋）
离场原因：回吐保护×29  信号反转×20  持仓超时×1
```

判读方式：

| 现象 | 含义 | 动作 |
|---|---|---|
| 留存 ≈ 峰值 | 落袋充分 | 不用动 |
| 留存 ≪ 峰值 | 回吐太多（就是你反馈的"贪"） | 调小 `--profit-arm` / `--profit-giveback` |
| 回吐保护占比极高、开仓数暴涨 | 锁得太紧，在噪声上来回进出 | 调大 `--profit-arm` |

参数含义：`--profit-arm`（默认 0.01）是**启动保护的浮盈高度**（占保证金比例）；
`--profit-giveback`（默认 0.4）是**允许回吐峰值的比例**。
先跑 `--dry-run` 攒几百轮，看上面这段输出，再决定往哪边调。

### 决策雷达：它此刻在想什么？

默认每 **30 秒**打印一段「思考过程」——不只是"在等什么"，
还包括**为什么持有、为什么做多/做空**：

```
[21:05:00] 雷达 30s｜轮 50｜权益 $9,972.69（-0.27%）｜持仓 2/2
[21:05:00]   风控｜止损 亏35%保证金｜回吐锁 浮盈1.0%起、最多回吐40%｜开仓门槛 |score|≥0.35｜成本门槛 3.0×
[21:05:00]   ▸ 持仓 USD/JPY 做多 5x｜入场 152.69424 → 现价 152.72305｜浮盈 $+1.13（+0.09% 保证金，峰值 +3.65%）
[21:05:00]       回吐锁已激活：锁 +2.19% 保证金，跌回即离场
[21:05:00]       当前 score +0.42（对做多单同向）→ 信号仍支持该方向 → 继续持有
[21:05:00]       因子贡献 tren+0.29 reve+0.13 → 净 +0.42
[21:05:00]   ▸ 开仓扫描 EUR/CHF score +0.63（门槛 0.35）→ 方向 做多
[21:05:00]       因子贡献 tren+0.52 mome+0.11 → 净 +0.63
[21:05:00]       → 持仓已满（2/2）
[21:05:00]   ▸ 学习器 权重 trend=+0.79 momentum=+0.21｜校准 β=+1.440e-04（非零 196）
```

**「因子贡献」是整段的核心，它不是事后解释。** 合成 score 的公式是

```
score = (Σ 因子值×权重 / Σ|权重|) × (1 + 波动率×0.55)
```

把波动率调节分摊到每一项，就得到每个因子的可加贡献，
**各项之和恰等于最终 score**（`Σ contrib ≡ score`）。所以这行
就是决策本身的来源：哪个因子在推、哪个在拖、净额多少，一目了然。
上例中趋势项 +0.52 和动量项 +0.11 都是正的，加起来正好 +0.63 →
"因为趋势和动量都看多，所以做多"。

**持仓那几行回答「为什么还拿着」**：浮盈相对保证金的位置、
回吐锁的当前触发线，以及**现在的信号是否还支持这个方向**。
四种可能的判决都会明说：

| 判决 | 含义 |
|---|---|
| 信号仍支持该方向 → 继续持有 | 原逻辑成立，什么都不用做 |
| 信号转弱 → 交给回吐锁/超时收尾 | 不再加仓，但不主动砍 |
| 信号已反向且够强 → 触发反转平仓 | 这就是本轮平仓的原因 |
| 信号已反向但强度不足 → 暂不动 | 想跑但证据不够，不折腾 |

**学习器那行**说明它现在信谁：

- **权重全零** = 学习器还没确认任何因子有 edge，此时 score 恒为 0。
  不开仓是设计使然，不是卡住了。
- **校准 β 未就绪** = 还没有足够证据估计「每单位 score 值多少收益」。
  此时成本门槛会退回命名常数 `score_to_return`（**不是**拒绝），
  所以不会把交易全挡死。
- **非零 N/M** 显示窗口里真正有信号可言的样本数。刚起步时
  score 恒为 0，光看总样本数会误判"够了"，所以额外要求非零样本数。

**「开仓扫描」那行**给出被拦的具体位置：信号强度不够 / 成本门槛不过 /
风控否决 / 持仓已满 / 开仓冷却，分别明说。

用 `--radar N` 调间隔（单位：**秒**，默认 30），`--radar 0` 关闭。

> 雷达按**墙钟时间**节流，不是按轮数 —— 轮数会随 `--interval` 变口径。
> 首次循环立即输出一行，之后每 N 秒一行。

> 踩过的坑：早期版本在校准未就绪时返回 `beta=0`，
> 下游看到"预期收益 = 0"就判"非正、不下注"，
> 于是永远退回不到常数兜底 —— 表现为策略在校准就绪前完全不交易。
> 现在未就绪时返回 `None`（= 未知），与"算出来是零"严格区分。

## 五、怎么读回测结果

**在合成基准环境（不带 `--csv`）下，正确的结果是"不赚钱"。**

这个环境是零漂移的随机游走，没有任何可预测结构。
如果策略在这里稳定大幅盈利，那只说明一件事：**程序里有未来函数泄露**，需要去查代码。

预期表现：

- 收益在零附近小幅上下波动，不呈现系统性方向
- 各因子 t 统计量普遍低于 `adapt_t_threshold`（默认 1.0），
  **权重全部归零** —— 系统主动空仓，而不是硬凑一个方向
- 已付手续费是主要的亏损来源
- 爆仓次数应为 0（风控生效）

> 注意：单次回测的"看起来赚了 2%"没有意义。
> 无结构市场的单次收益波动本身就有几个百分点，
> 必须用 `final_report.py` 的多市场 × 多种子 × t 检验来看。
> 实测该环境在 24 种子下是 **−0.32%（t=−0.34）**，与 0 不可区分——
> 这才是正确的结果。

看报告时优先关注这三个指标：

1. **最大回撤** —— 代表最坏情况下的痛苦程度，比收益率重要
2. **手续费/毛利** —— 如果接近或超过 100%，说明交易太频繁，
   赚的钱全交给成本了
3. **IC 与 t 统计量** —— 判断因子是否真有效。
   `|t|` 低于 `adapt_t_threshold`（默认 1.0）就没有可信 edge，
   该因子不获得权重。注意 t 统计量**带符号**：负值表示该因子与未来收益
   负相关，系统会把它**反着用**（给负权重），这是正常且预期内的行为。

## 八、当前进度与下一步

**最终版定案（v1.0）：自适应多因子 + 在线校准成本门槛。**

策略在经历多轮诊断后**收敛**为一个明确方案，不再继续堆因子。
选择它的理由是它**诚实**：在结构足够强时（`trend_strong`）
拿到 t=+8.5 的显著收益，在结构不足时自动收敛到保本附近，
而不是靠噪声刷出好看的回测曲线。

关键结论与定案依据见第二节的
**「最终版实测结果（诚实版）」**与**「为什么 `cost_multiple` 最终定在 3.0」**。
最重要的一句：**这不是一个"稳定盈利 5%"的系统**，
它的期望值取决于目标市场里实际有多少可提取的结构。

**观测量：`python run.py strategy` + 决策雷达。**
不要靠"感觉它没在动"来判断策略状态 —— 用 `run.py strategy` 看参数，
用 live 的雷达行看「当前最强信号 / 被哪道闸门挡住 / 权重 / 校准 β」。

**已修复的方向性 Bug（都会造成"看起来在跑、其实跑偏"）：**

| Bug | 表现 | 修复 |
|---|---|---|
| 「等权 = 无信号」判据反了 | 显著因子越多越禁止开仓 | 改为「权重是否全为零」 |
| `copysign(mean, 1.0)` 恒返正 | 因子永远无法被反用 | `copysign(strength, mean)` |
| 校准未就绪返回 `beta=0` | 常数兜底永不生效，就绪前完全不交易 | 未就绪返回 `None` |
| 成本门槛符号算错 | 只做多，做空被一律拒绝 | 先判 `beta>0`，再比 `\|expected\|` |
| `--dry-run` 仍被 `--yes` 拦住 | 干跑跑不起来 | 干跑不要求 `--yes` |

**已完成的工程能力**：真实交易闭环 + 提示浮层自动关闭（v0.6）、
桥接等待窗口 60 秒并带进度提示、`strategy` 子命令、决策雷达。

**当前局限：**

- **唯一稳健的 edge 只在强趋势市场**（详见"最终版实测结果"）：
  `trend_strong` 上 +43.9%（t=+11.6），其余档位都在噪声内 ≈ 保本。

- **强均值回归市场是短板**：`revert_strong` 只有 −0.08%、
  平均 1.2 笔开仓。平仓逻辑偏趋势（追踪止盈 + 超时 + 信号反转），

- 只做了单标的独立决策，没有跨品种的协整/对冲逻辑
- 因子库只有 4 个，且都是最经典的形态

- live 模式的行情输入比回测稀疏（游戏只给当前报价，没有高低价），
  ATR 会退化为相邻报价差的均值 —— 这是数据可得性上的正常降级，
  程序不虚构拿不到的数据
- **平仓时的盈亏是估算值**：来自平仓前读到的浮动盈亏，
  不是券商回执的实际成交值。权益终值以页面上
  `span.money-large` 为准
- 长时间稳定性未验证：目前实测只跑到几十轮，
  尚未验证数小时连续运行的稳定性

**已修复的缺陷（开发中的教训）：**

| 缺陷 | 根因 | 修复 |
|---|---|---|
| 干跑模式 100 轮开 94 笔、平 0 笔 | `DryRunExecution` 返回假 ID，假持仓不出现在 `state()`，引擎每轮误判可再开 | 虚拟持仓表 + 开仓冷却 `entry_cooldown_ticks=5` |
| 实盘找不到表单 | DevTools 打印的 name 是回退名，非真实属性 | 改用真实 id，`pick()` 多级回退 |
| 保证金解析误取名义价值 | 页面文本 "多$500.00 保证金 $10,000.00 仓位" | 正则优先左取 `\$([\d,]+)\s*保证金` |
| 面板一直显示 `[顶层]` | 油猴默认只在顶层运行，iframe 内无 `.pair-row` | 「仅在顶层页面运行」= 否 + 重启扩展 |

| **强结构市场反而完全不交易** | 「等权=无信号」判据方向反了：4 因子时等权是 0.25 ≤ 0.38 上限，导致**显著因子越多越被判为无信号**而禁止开仓 | 判据改为"权重是否**全为零**"，与是否均匀无关 |
| **因子符号被抹掉，反向指标无法反用** | `math.copysign(mean, 1.0)` 恒返正数 | 改为 `math.copysign(strength, mean)` |
| **t 统计量被重叠样本高估** | `eval_horizon` 期内每个时点都登记预测，样本高度重叠 | 登记时降采样：`now % eval_horizon == 0` 才记录 |
| 学习器"死锁"、永不交易 | `t_threshold=2.0` 需要约 1231 个独立样本才显著，而 lookback 仅 240 → t 最大 0.88 → 权重恒 0 | `t_threshold` 降至 1.0、`lookback` 提至 400、校准器登记含 score=0 的样本 |
| `MAX_HISTORY=25` 导致长跑交易记录被截断 | 前 25 笔丢失，K 线纪律测试"空跑假通过" | 提到 500，并给测试加有效性断言 |
| 成本门槛假设 8bp 点差，与实际不符 | 臆测的保守值把往返成本抬到约 9.5bp，信号优势通常只有几个 bp → 全部交易被挡掉 | 实测确认游戏只有单一报价，`spread_estimate` 默认改 0 |

**下一步的优先级建议：**

1. **改掉强均值回归市场的短板**——这是目前最清楚的能力缺口
2. 验证长时间运行的稳定性（数小时连续跑，观察内存与累计误差）
3. 让平仓盈亏取真实回执值，而非平仓前估算
4. 用真实历史汇率数据跑回测，看因子在真实市场里的表现
5. 补充 walk-forward 检验，确认参数不是过拟合出来的
6. 扩充因子库（波动率期限结构、多周期共振、跨品种价差）
